# 第三批：恢复、有限重试与保存幂等

日期：2026-11-25。分支：codex/ai-reliability-four-batches。仅本地实现，尚未推送或发布云端。

## 修改

- `ai_run.py`：纪要分段与合并按输入、Prompt、模型参数及原纪要计算运行标识；成功阶段经再次校验后复用。每次尝试单独保存请求、原始响应、结构校验结果和结束状态，不覆盖旧尝试。只有写入分析文档后才记录任务完成。
- `web_app.py:generate_familiarity_memo`：接入上述运行记录。SDK 内置重试关闭，每阶段最多三次尝试；网络、429、服务端错误及无效结构有限重试，401 等永久错误不重试。再次点击生成时，输入一致的已完成阶段不再收费调用。原文或原纪要变化则不能复用旧任务。
- `web/app.js`：失败状态明确提醒再次生成可以复用成功阶段；仍保留第一批的所属访谈检查。
- `web_app.py:save_theme_analysis`、`web/theme.js:saveThemeAnalysis`：客户端重用同一请求标识；服务端在文档锁内检查内容摘要，相同请求只保存一次，同标识不同内容返回 409。

## 边界与风险

- 这里实现的是纪要阶段恢复，不是所有 AI 功能的统一队列；主题分析沿用已有恢复机制，旧编码、摘要和比较调用的重试/恢复仍需后续统一。
- 单进程文档锁不等于跨进程分布式互斥。缓存只保证输入一致的已验证阶段复用，不能保证供应商在网络中断后绝不计费。
- 幂等标识在当前前端对象内保留；关闭网页后不保证恢复客户端标识，不能宣称跨设备 exactly-once。
- 私有运行目录含输入与输出文本，不含 API Key；部署时需沿用服务私有目录与权限，后续应增加保留期、容量清理及用户告知。公共结构化日志只记录标识与错误类型。
- 格式错误重试仍使用相同任务约束，没有假装用局部修补就证明语义质量；第四批单独检验分块和 Prompt。
- 本批真实模型调用 0 次，累计 0/100。云端未发布。
