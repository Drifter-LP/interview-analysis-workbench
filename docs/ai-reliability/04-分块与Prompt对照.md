## Prompt Review: 纪要、初始编码与索引

### Scope

- 位置：`web_app.py:generate_familiarity_memo`、`interview_coding.py:CODING_PROMPT`、`indexed_theme.py:INDEX_PROMPT`。
- 模型：deepseek-flash、qwen3.8-flash。用途：原文提取/概括、编码、索引；system 与 JSON user 分开。长度约数百至一千余输入 Token，实际逐次记录见 trace。
- 本批是在此前全项目审查基础上做定点修复，不宣称其余全部 Prompt 已重写或实测。

### Major

- [M1，已处理并小样本复测] 原约束“先用一段120至200字的summary”，短材料也被迫扩展。第三轮无答案输出出现原文不存在的“需要另择时间再行访谈”。最后一版允许更短，并禁止加入建议。
- [M2，已缓解但保留语义风险] 引文逐字一致不代表结论受证据支持。首轮新版及第二轮重复测试出现“费用担忧与拒绝服务之间没有直接因果关系”或“不直接导致”的表述；原文只说个人担心费用但没有拒绝。加入明确约束、反例后，第三轮三次重复的观点标题改为“担心费用但未拒绝服务”；第四轮四个样本未观察到该错误。不能推广为总体准确率。
- [M3，剩余] 超长单句硬拆、只保留 400/600 字符的上下文仍可能不足；全文索引和纪要汇总尚非层级递归架构。预算过大时明确终止，不通过截断换成功。

### Minor

- temperature=0 不保证输出稳定；只对一个否定用例做了三次重复对照，并非全面稳定性评估。
- 当前纪要严格拒绝重复而无法唯一定位的引文，可能使真实长稿中的合理重复表述失败；需进一步设计显式原文位置契约，而非恢复第一次字符串匹配。

### What's done right

- 保留逐字引用、说话人区分、未知字段写“未说明”、不强制观点数量；先做程序契约校验，再检查具体内容。
- 参数与模型固定，新旧请求和原始响应均保留；新 Prompt 不会覆盖旧尝试记录。

### Quick wins / 后续优先级

1. 用研究者逐条确认的样本建立语义回归集；本轮没有用户标注，不伪报人工语义通过率。
2. 再做超长真实结构的合成问答、多材料整合与遗漏率测试，建立索引层级预算及关键条件覆盖指标。
3. 将其他旧调用的重试、原文最终版本校验和运行记录逐步统一，避免宣称本批已全覆盖。
